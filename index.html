不是论文翻译，也不是 API 调用合集。这份教程从"这个词是什么意思"讲起，一路讲到 召回怎么切、模型怎么选、特征怎么造、线上怎么扛住延迟、指标跌了怎么查， 最后用两个数据全部仿真、结果可复现、经得住追问的项目把整条链路走完。

先说你最关心的三件事。

1）能不能看懂？——每个概念都先给一句人话定义，再给公式，再给"在系统里它到底出现在哪一步"。看不懂的地方，基本都配了图和例子。

2）学完能不能干活？——两个项目都是从"业务背景 → 数据长什么样 → 怎么建模 → 效果多少 → 线上怎么部署 → 被人追问怎么答"的完整闭环，不是跑个 demo 就结束。

3）数据是不是编的？——是仿真的，但生成逻辑写死在脚本里（用户隐向量、内容质量、位置偏差、时效衰减），所以模型效果的差异是可解释、可复现的，不是随机数凑出来的漂亮曲线。

WHY为什么搜广推值得系统学

因为它是"算法离钱最近"的方向，也是少数能把机器学习、工程、业务三者同时练到的场景。

PROJECTS两个项目，两种叙事

项目一 · 互联网

"抖风"短视频推荐系统

2 万用户、5000 条视频、31.8 万条曝光日志。从热门/ItemCF/双塔三路召回，到 LR/FM/DeepFM/DIN 四代排序模型，再到多样性与打散重排。

亮点：指标是真的跑出来的。AUC 从 0.500（均值基线）→ 0.847（LR）→ 0.858（DIN）；双塔 Recall@100 11.3%，热门只有 9.7%。每一个数字都能在脚本里复现。

适合回答：你怎么做召回？为什么 DIN 比 DeepFM 好？离线涨了线上一定涨吗？

项目二 · 政务/行业

惠企政策"政策找人"平台

8000 家企业、120 条政策。核心不是模型多深，而是规则优先、语义兜底、结果可解释、过程可审计。

亮点：规则引擎召回率 100%、精确率 91.7%；规则+语义召回把 Recall@10 从 67.8% 提到 78.7%，误推率从 21% 降到 7.8%；并给出不同规模企业的曝光公平性分析。

适合回答：政务场景为什么不能纯用大模型？漏推和误推哪个更严重？怎么让企业信这个推荐？

上面这些词有一个说不清？先看 第 1 章的"读前 10 分钟补课"，那里用一张表 + 三个公式把 embedding、sigmoid、AUC 这些词先讲成人话。

不需要（会在文中补）

  • 深度学习框架细节——代码都是最小实现

卡住了怎么办：遇到不认识的词，先翻 术语速查（52 条），再回到原文； 公式看不懂时，先看这一节"为什么需要它"，别死磕推导。术语速查的定位是"随时可查的字典"，不需要通读。

REPRODUCE关于仿真数据与复现

两个项目的数据都由脚本生成，没有使用任何真实用户数据，可以放心写进简历和公开分享。生成逻辑遵循真实业务里的因果结构：

仿真机制对应真实业务为什么重要
用户隐向量 × 内容隐向量用户兴趣与内容主题的匹配让"个性化"真的有效，模型才有可学信号
位置 1~4 的点击加成首位偏差（position bias）解释为什么离线 AUC 会虚高、线上要 debias
发布时间衰减内容时效性让"新鲜度特征"有必要存在
政策硬条件 + 字段缺失政务数据质量与合规底线证明"规则优先"不是落后，而是业务要求

复现命令：python scripts/gen_project1.py、python scripts/gen_project2.py。依赖：numpy、pandas、scikit-learn、torch（CPU 即可）。生成后的指标写入 data/p1_metrics.json 与 data/p2_metrics.json，页面里的图全部由这些文件驱动。

数据与脚本：点开就能看，不用信我
