预测算法进阶：从“跑出 MAPE”到“能支撑决策”

第 4 章解决了“怎么做一个能用的预测”。这一章补三件更专业的事：怎么定义好任务、怎么证明模型真的更好、怎么让预测带着不确定性进入决策。面试里区分“会用库”和“懂预测”的，通常就是这三件事。

预计 100 分钟 前置：第 4 章 产出：能选型、能调参、能给出区间 性质：算法深度
先校准一个观念：预测不是终点

业务真正需要的是决策：买多少电、充多少电、报多少容量、要不要派人核查。点预测只回答“最可能多少”，概率预测回答“有多大可能超过某个值”。储能、需量、需求响应这些场景，后者往往比前者更有价值。

先把任务说清楚：预测问题的六个维度

维度选项对项目的影响
输出形式点预测 / 区间 / 概率分布决定损失函数与评估指标
步长单步 / 多步（24 点、96 点）多步要考虑误差累积或直接多输出
多步策略递归 / 直接 / 多输入多输出递归简单但误差累积；直接多模型成本高
建模范围单序列局部模型 / 多序列全局模型全局模型能共享规律，冷启动测点更友好
层级单层 / 分层（园区→楼栋→测点）需要一致性对账，否则加总对不上
更新方式离线批量 / 定时重训 / 在线学习决定工程复杂度与漂移响应速度

项目一的选择是：点预测、24 步、直接多输出（一个模型 + horizon 特征）、全局单模型、单层、离线批量。这个组合不是唯一正确答案，但它用最低的工程复杂度覆盖了“日前 24 点”这个需求。面试时能解释“为什么不选另外几种”，比单纯说“我用了 LightGBM”更有分量。

递归 vs 直接：一句话判断

如果你能接受“训练一个模型、预测时滚动 24 次”，选递归；如果误差累积不可接受、且样本足够，选直接多输出。项目一选直接，是因为 24 个 horizon 可以共享同一套特征，且避免了“第 24 步用到第 23 步预测值”的误差累积。

指标体系：MAPE 不是万能的

指标定义适合陷阱
MAE平均绝对误差，单位同负荷业务解释直观大负荷测点主导全局指标
RMSE均方根误差，惩罚大误差关注极端偏差对离群值敏感
MAPE平均绝对百分比误差跨测点可比真实值接近 0 时爆炸；低谷不适用
sMAPE对称 MAPE缓解分母过小仍有界但不直观
WAPEΣ|误差| / Σ|真实值|聚合口径、含零值会被大值主导
MASE相对朴素基线的 MAE跨数据集比较需要定义季节性基线
Pinball分位数损失概率预测不同分位数不可直接平均
Coverage真实值落在区间内的比例区间质量区间越宽越容易覆盖，要同时看宽度
坑：用 MAPE 评估夜间低谷

夜间负荷可能只有峰值的 30%，同样的绝对误差在夜间会放大成很大的百分比。项目一里谷段 MAPE 2.01%、峰段 1.51%，不是模型在谷段更差，而是分母更小。正确做法是分时段报告，并在决策场景改用 MAE 或 WAPE。

基线不是形式：它决定了你的“提升”是否可信

基线定义什么时候必须报
昨日同期用昨天同一时刻的值所有短期负荷预测
上周同期用上周同一天同一时刻周周期明显时
季节朴素用上一个相同季节周期的值日/周/年周期
移动平均最近 k 个同时刻点平均波动大的场景
线性回归少量特征的线性模型验证特征是否真的有用

传统方法：什么时候它们仍然是最优解

方法原理适用 / 不适用
ARIMA用自回归、差分、移动平均描述序列单序列、平稳化后规律明显；难吃多源特征
SARIMAXARIMA + 季节项 + 外生变量有温度等外生变量、样本不长时很稳
指数平滑（ETS）对近期观测加权，含趋势/季节快速基线、平滑序列；对突变响应慢
Prophet趋势 + 季节 + 节假日分解可解释、上手快；对精细气象与突变弱
Theta对序列做 theta 变换后外推M3/M4 竞赛表现好，单变量基线强

不要因为“树模型更强”就否定传统方法。它们的价值在于：样本少、可解释性要求高、需要统计检验、要快速给业务一个基线。面试被问“为什么不用 ARIMA”，正确回答是“我跑过，作为基线 MAPE 是多少；但本任务有多源特征和 24 步输出，树模型更合适”，而不是“ARIMA 过时了”。

树模型进阶：三个容易被忽略的细节

① 目标变换

负荷右偏、峰值很大时，对目标做 log1p 再训练，可以减小大值对损失的支配。但要注意：反变换后会有偏差（exp 是凸函数），需要做偏差修正，或者干脆用 MAE/Huber 这类稳健损失。

② 类别特征

测点 ID、类型、楼栋这些类别特征，LightGBM/CatBoost 可以直接处理；XGBoost 需要编码。多测点全局模型里，类别特征往往是“让一个模型适配不同曲线”的关键。

③ 单调约束

如果业务上确定“温度越高、制冷负荷越大”，可以给温度特征加单调约束，减少反直觉的预测。代价是模型灵活性下降，需要验证是否真的单调。

模型特点实践建议
LightGBM训练快、内存省、叶生长策略中小数据首选，调参成本低
XGBoost生态成熟、正则化强特征多、需要更稳的正则时
CatBoost类别特征处理好、默认参数强多测点、类别多、懒得调参时

调参：Optuna + 时间序列交叉验证

网格搜索在 5 个以上超参时成本爆炸。用贝叶斯优化（Optuna）配合时间序列交叉验证，既省算力又能避免随机切分带来的泄漏。

Optuna + TimeSeriesSplit（骨架）
import optuna
from sklearn.model_selection import TimeSeriesSplit

def objective(trial):
    params = {
        "n_estimators": 3000,
        "learning_rate": trial.suggest_float("lr", 0.01, 0.1, log=True),
        "num_leaves": trial.suggest_int("leaves", 31, 255),
        "min_child_samples": trial.suggest_int("mcs", 10, 80),
        "subsample": trial.suggest_float("sub", 0.6, 1.0),
        "colsample_bytree": trial.suggest_float("col", 0.6, 1.0),
    }
    scores = []
    for tr, va in TimeSeriesSplit(n_splits=3).split(X):
        model = lgb.LGBMRegressor(**params)
        model.fit(X.iloc[tr], y.iloc[tr], eval_set=[(X.iloc[va], y.iloc[va])],
                  callbacks=[lgb.early_stopping(60, verbose=False)])
        scores.append(mean_absolute_error(y.iloc[va], model.predict(X.iloc[va])))
    return sum(scores) / len(scores)

study = optuna.create_study(direction="minimize", sampler=optuna.samplers.TPESampler(seed=42))
study.optimize(objective, n_trials=30)
两个调参陷阱

① 用测试集调参：反复看测试集分数会过拟合测试集，最后上线崩。正确做法是训练/验证/测试三段，验证集调参，测试集只看一次。② 早停轮数不稳定：不同随机种子下最佳迭代数可能差很多，导致模型容量不可控。可以固定树数，或用多折平均最佳轮数。

深度学习：什么时候值得上

模型擅长现实建议
LSTM/GRU序列依赖、长短期记忆数据量中等时不一定赢 GBDT；调参成本高
TCN因果卷积，训练并行比 LSTM 稳，仍需要足够样本
Seq2Seq多步输出、编码器-解码器适合 96 点等多步任务
Transformer / Informer长序列、注意力数据大、算力足才值得；小数据易过拟合
PatchTST把序列切 patch，降复杂度长序列预测的实用选择
TFT多变量 + 可解释注意力需要概率输出、可解释性时
N-BEATS / N-HiTS纯 MLP 结构，多步单变量强基线，工程简单
一句实话

在园区级、几十个测点、两年数据这个量级，调好的 LightGBM 往往不输深度学习，而且训练快、可解释、部署简单。深度学习的价值在“多序列、大数据、长历史、复杂多变量”场景。面试时不要为了显得高级硬上 LSTM，能说清“我试过，没赢，所以没用”反而加分。

概率预测：让预测带着“不确定”进入决策

业务问题往往不是“明天用多少”，而是“明天有多大概率超过 2000 kW”。这时需要分位数预测或预测区间。

方法二：Conformal 预测（推荐先学）

先用点模型得到预测，再用验证集的残差分位数构造区间。它不假设分布，覆盖率的解释性很强，工程上也好落地。

Split Conformal 区间
# 1) 在验证集上算绝对残差
resid = np.abs(y_val - model.predict(X_val))

# 2) 取 90% 分位数作为区间半宽
q90 = np.quantile(resid, 0.9)

# 3) 测试时输出 [pred - q90, pred + q90]
lo = pred - q90
hi = pred + q90
# 覆盖率应接近 90%；如果明显偏低，检查验证集是否与测试集同分布
坑：分位数交叉

独立训练的分位数模型可能给出 P10 > P90 的荒谬结果。解决：训练后做排序（np.sort 沿分位数轴），或用支持多分位数的联合模型，或用 conformal 方法绕开这个问题。

层级预测与对账：加总对不上怎么办

园区总负荷 = 各楼栋之和，楼栋 = 各测点之和。如果分别预测，再加总，很可能对不上。这叫层级不一致。

方法做法特点
Bottom-up预测最底层，再向上加总一致性好；底层噪声会累积
Top-down预测顶层，再按历史比例拆分稳定；忽略底层变化
MinT / 最优对账各层独立预测后，用协方差做加权调整理论上最优，实现复杂
简单按比例调整先各自预测，再按顶层总量缩放工程简单，效果常够用

项目二没有做层级预测（40 个测点各自独立），但如果你做的是“园区→楼栋→测点”，就必须处理这个问题。面试被问“总负荷和分项对不上怎么办”，能说出 MinT 或比例对账，就已经超过多数候选人。

组合、后处理与峰值修正

组合预测

多个模型取平均（简单平均、按验证集误差加权、堆叠）。组合通常能降低方差，但要保证各模型误差不完全相关，否则收益有限。

后处理

偏差校正（整体偏低就加回均值偏差）、峰值修正（峰段单独建模或加惩罚）、负值截断、爬坡率限制。后处理要可解释、可回滚。

峰值修正要谨慎

业务最在意峰值，但专门给峰值加权容易过拟合。更稳的做法是：分时段建模、加入“是否峰段”特征、或用分位数 P90 作为保守估计。任何修正都要在验证集上验证，不能凭感觉调。

漂移与重训练：模型会过期

漂移类型表现应对
数据漂移输入分布变了：新增测点、温度范围变化监控输入统计，更新特征
概念漂移同样的输入，输出关系变了：新产线、电价调整重训练、加新特征
标签延迟真实值晚到，精度指标滞后用代理指标（如预测分布）先监控
突发冲击疫情、限电、设备改造人工干预 + 快速回滚
重训练策略怎么定

固定周期（每周/每月）最简单；按漂移触发更省算力；两者结合最稳。关键是重训练也要走验证与灰度，不能自动覆盖线上模型。项目里没有实现自动重训练，但第 6 章给了监控指标与回滚流程，这是刻意保留的工程边界。

常见坑

坑后果正确做法
用随机切分评估时序分数虚高，上线崩按时间切分，必要时滚动验证
用测试集反复调参测试集过拟合训练/验证/测试三段，测试只用一次
只报 MAPE低谷误差被放大，误导决策分时段 + MAE/WAPE 一起报
忽略基线无法证明模型有价值至少报昨日同期
分位数不排序区间上下界颠倒排序或联合建模
层级不一致总表与分项对不上对账或 bottom-up
过早引入深度模型成本高、效果不稳定先 GBDT，再按收益决定

自测：能不能撑住追问

  • 能说清你的任务是“点/区间、单步/多步、递归/直接、局部/全局”。
  • 能解释为什么 MAPE 在低谷会变大，以及你会补哪个指标。
  • 能说出至少两个基线，并给出它们的分数。
  • 能解释 Optuna 里为什么用 TimeSeriesSplit 而不是 KFold。
  • 能写出一个 conformal 区间，并说明覆盖率怎么验证。
  • 能解释层级预测为什么会对不上，以及两种对账方法。
  • 能给出一个漂移监控指标和对应的重训练触发条件。
