电力与能源行业基础：先懂物理，再谈算法

这一章不讲模型，只补你最缺、也最容易被面试官一眼看穿的东西：电是怎么计量、怎么定价、怎么结算的。学完你应该能看懂一张电费单、说清一个测点的数据从哪来，并且不再把 kW 和 kWh 混着用。

预计 90 分钟 前置：第 1 章（建议同步读） 产出：能解释电费构成与数据口径 性质：背景 / 行业知识
先说清楚：这一章解决什么

算法工程师的绝大多数“看起来像模型问题”的错误，最后都能追到三件事：单位错了、口径错了、物理约束漏了。比如把 15 分钟功率直接求和当电量、把月度最大需量当成日最大值、把光伏出力当成负荷。这些错误不会报错，只会让结论安静地偏掉。补这一章，是为了让你在写第一行特征代码之前，就知道每个数字代表什么。

为什么算法工程师要补电力常识

① 单位错：差 4 倍或 1000 倍

功率是 kW（瞬时），电量是 kWh（累计）。15 分钟一个点，功率 × 0.25 h = 电量。把 96 个功率点直接相加，得到的不是日电量，而是一个没有物理意义的数。

② 口径错：同一句话两种意思

“最大负荷 2000”是 kW 还是 kVA？“这个月用了 80 万度”是总电量还是峰段电量？口径不写清楚，模型评估和收益核算都会对不上账。

③ 约束漏：算出来的方案执行不了

储能不能同时充放电、SOC 不能越界、并网不能超容、电池不能无限循环。优化模型里少一条约束，结果就会“很漂亮但没法用”。

一条判断标准

如果你不能用一句话说清“这个字段的单位、采样频率、统计口径、谁在用”，那这个字段就还不能进模型。先把这句话写进数据字典，再写代码。

电力系统：电从哪来，到哪去

电力系统可以粗暴地分成五段：发电 → 输电 → 变电 → 配电 → 用电。你所在的园区 EMS，几乎全部发生在最后两段；但你的数据质量，取决于前面每一段。

环节典型电压等级你可能会接触到的数据
输电220 / 330 / 500 / 750 kV，直流 ±800 kV一般拿不到；最多是电网下发的关口计量与结算电量
变电110 / 35 / 10 kV关口表、主变容量、需量、功率因数、负荷曲线
配电10 kV / 380 V台区总表、分支表、居民/商户表；线损分析的统计单元
用电380 / 220 V楼栋、车间、产线、充电桩、光伏逆变器、储能 PCS 的秒级/分钟级数据
为什么“实时平衡”决定了预测的价值

电能不能大规模、低成本地储存（储能成本仍高），所以发电必须几乎实时等于用电。这个物理事实带来两个直接后果：① 负荷预测是电力系统的基础输入，不是“可选的增值功能”；② 预测误差会转化成真金白银——多买要退、少买要补，偏差还可能被考核。这就是这个岗位存在的根本原因。

四个必须分清的量：功率、电量、需量、容量

这四个词在日常对话里经常被混用，但在数据和结算里是完全不同的东西。下面这张表建议直接背下来。

量单位定义在项目里的样子
功率kW 某一瞬间的用电速率。电表每 15 分钟记录的是这段时间的平均功率。 项目一的 load_mw、项目二的 p_kw
电量kWh 一段时间内累计的电能，等于功率对时间的积分。 电费单上的“用电量”、储能充放电量、光伏发电量
需量kW 一个计费周期内，按固定窗口（常见 15 分钟）统计的平均功率最大值。 基本电费的计算依据；储能削峰的直接目标
容量kVA / kW 设备或合同允许的最大功率能力，是“上限”而不是“实际值”。 变压器容量、并网容量、储能功率上限、测点容量字段

功率 → 电量：乘时间

电量(kWh) = 功率(kW) × 时长(h)。15 分钟 = 0.25 小时，所以 96 个点求和后要乘 0.25（如果单位是 kW）。项目二的原始表只存了功率 p_kw，电量要在分析时按 0.25 小时折算，不能直接相加当 kWh。

电量 → 平均功率：除时间

一天用了 19,200 kWh，平均功率就是 19200 / 24 = 800 kW。这个数不等于最大需量——负荷有峰谷，平均值会显著低于峰值。

坑：电表读数是累计值，不是瞬时功率

很多电表存的是“正向有功总电量”这类累计读数（kWh），每次抄表得到的是递增的数字。你必须做差分（后一条减前一条）才能得到区间电量，再除以时间得到平均功率。直接拿累计值当负荷建模，会得到一条单调上升的斜线。

有功、无功、功率因数

交流电里，真正做功的是有功功率（kW），建立磁场的那部分是无功功率（kvar），两者合成视在功率（kVA）。三者关系：

三个功率的关系
视在功率 S (kVA) = √(P² + Q²)
功率因数 cosφ   = P / S

# 例：P = 800 kW，Q = 600 kvar
# S = √(800² + 600²) = 1000 kVA，cosφ = 0.8
# 功率因数低于考核标准（常见 0.9）会产生力调电费罚款

这就是为什么很多园区要装无功补偿装置：不是为了省电量，而是为了把 cosφ 提到 0.9 以上，避免力调电费罚款。做负荷预测时通常只关心有功；但做容量规划和电费核算时，必须看视在功率。

计量与采集：一行数据是怎么来的

一条“2024-08-01 00:15, M013, 412.6 kW”的记录，背后经过了很多环节。任何一环出问题，你看到的就是缺失、重复、跳变或倍率错误。

一次侧：电压互感器（PT）与电流互感器（CT）

高电压、大电流不能直接进表，要先按比例降到表能接受的范围。这个比例就是“变比”，也就是常说的倍率。

二次侧：电能表计量

电表按 15 分钟（或 1 分钟）统计平均功率、累计电量、最大需量、事件记录（失压、失流、开盖等）。精度等级常见 0.2S / 0.5S / 1 级 / 2 级。

采集：网关 / 集中器

通过 RS-485、载波（HPLC）、4G 等把表里的数据抄上来。网关通常有本地缓存和断点续传，断网恢复后会补传。

上传：规约转换

把电表规约（如 DL/T 645）转成平台能接收的格式，经 MQTT / HTTP / IEC 104 上传。

落库：时序数据库

按测点打标签写入。这里会出现重复、乱序、时区错、单位不统一等第二波问题。

倍率（综合倍率）怎么算
综合倍率 = CT 变比 × PT 变比

# 例：CT 300/5 = 60，PT 10000/100 = 100
# 综合倍率 = 60 × 100 = 6000
# 表码差 100（kWh）→ 实际电量 100 × 6000 = 600,000 kWh

# 项目二里 meter_meta.csv 存了 ct_ratio 字段；
# 倍率配错会让整条曲线系统性放大/缩小，是最典型的“整表异常”
坑：倍率错误看起来像“用电暴涨”，不像数据错误

倍率从 1 改成 3，曲线整体抬升 3 倍，形状完全正常。基于形状的异常检测（比如同比、同业基线）很容易把它判成“用电异常”而不是“计量异常”。所以项目二里单独设了“倍率类”规则：与同类型测点的水平比值持续偏离，且形状相关性仍然很高。

常见通信规约：不用会写，但要知道谁在说话

规约用在哪你需要知道的一句话
DL/T 645多功能电能表国内电表最常用的抄表规约，按“数据标识”读电量、需量、事件
DL/T 698.45面向对象的用电信息采集比 645 更现代，支持更多对象与参数
IEC 60870-5-104调度/变电站远动常说的“104 规约”，传遥测、遥信、遥控
IEC 61850变电站自动化面向对象的变电站通信标准，模型化程度高
Modbus RTU/TCPPLC、逆变器、PCS、BMS工业设备最常见的“寄存器读写”，点位表就是它的字典
MQTT网关到云平台轻量发布订阅，适合大量设备上行
HPLC台区电表本地通信高速电力线载波，不用额外布线，但受台区噪声影响
采集质量三个指标

采集成功率：应采点数中成功采到的比例；完整率：一天 96 点里实际有多少点；及时率：数据在规定时间前到齐的比例。这三个指标通常写在运维考核里，也直接决定你的特征能不能按时算出来。项目二的质量分只用了完整率与容量合理性，是简化版。

台区与线损：行业里最常用的两个分析单元

台区是一台配电变压器供电的范围。台区总表（供电量）减去所有用户表之和（售电量），差值就是线损。线损率突然升高，常见原因有三个：窃电、计量故障、户变关系错（用户的表被挂到了别的台区）。

线损率的计算与判断
线损率 = (供电量 - 售电量) / 供电量 × 100%

# 例：台区总表 12,000 kWh，用户表合计 11,100 kWh
# 线损率 = (12000 - 11100) / 12000 = 7.5%
# 若历史稳定在 4%~5%，突然升到 7.5%，优先排查窃电/计量/户变关系

注意：线损率有合理的物理下限（变压器损耗、线路损耗），不是越低越好；不同台区、不同负载率之间也不能直接横向比较。项目二没有做台区级线损，因为仿真的是 40 个独立测点，这是一个明确的简化。

EMS 家族：SCADA、EMS、DMS、BMS、PCS 分别管什么

招聘里写“EMS”，但真实项目里你会同时听到一堆系统名。它们的边界如下，至少要知道谁给你数据、你给谁结果。

系统管什么典型数据和你的关系
SCADA实时监视与控制，秒级采集遥测遥信电压、电流、开关状态、告警设备级实时数据源；你的模型通常不用秒级，但要能对接
EMS能源管理：计量、分析、报表、优化15 分钟负荷、电费、需量、能流你的算法最主要的宿主系统
DMS配电管理：台区、线损、停电、抢修台区总表、用户表、停电事件窃电/线损分析的上游
BMS电池管理：SOC、SOH、单体电压、温度电池状态与保护信号储能调度的硬约束来源
PCS储能变流器：充放电功率控制实际充放电功率、可用功率你的调度指令最终下发给它
微电网园区内源网荷储的自治运行光伏、储能、负荷、并网点调度问题的物理边界
虚拟电厂（VPP）聚合可调资源，参与电网需求响应/辅助服务可调容量、申报量、响应量把“园区内的优化”变成“市场收益”
碳管理平台碳排放核算、绿电绿证、碳资产电量、排放因子、绿电比例把电量换算成碳，口径必须统一
怎么快速搞清楚一个陌生项目的系统边界

问四个问题：① 数据从哪个系统来、多久一次？② 结果写回哪个系统、谁看？③ 谁能下发控制指令、有没有闭锁？④ 出问题谁负责？这四个答案决定了你的接口、延迟要求和验收标准，比读十页架构文档都有效。

电价：一张电费单是怎么算出来的

储能套利、需量控制、需求响应，全都建立在电价结构上。看不懂电费单，就不可能算对收益。

电费通常由五块组成

组成怎么算你的算法能不能影响
电度电费分时段电量 × 对应电价（峰/平/谷/尖峰）能：储能把电量从峰段搬到谷段
基本电费按变压器容量（元/kVA·月）或按最大需量（元/kW·月）能：削峰降低最大需量
力调电费按功率因数高于/低于考核标准进行奖励或罚款间接：无功补偿，通常不是算法职责
政府性基金及附加按电量固定加收不能
偏差/考核费用参与市场交易时，实际与申报偏差产生的费用能：更准的预测降低偏差
两部制电价：为什么“少用电”不一定“少交钱”

大工业用户常见两部制：电度电费按用电量收，基本电费按容量或需量收。这意味着即使你这个月一度电没用，只要变压器容量还在，基本电费照收。反过来，如果你把峰值压下去、把负荷填到谷段，电量可能没少，但电费明显下降——这正是储能和需求响应的商业逻辑。

一张简化的月度电费单（示意数值）
# 示意：某园区一个月
peak_kwh, flat_kwh, valley_kwh = 180_000, 420_000, 260_000
price = {"peak": 1.15, "flat": 0.72, "valley": 0.38}   # 元/kWh，示意

energy_fee = (peak_kwh * price["peak"]
              + flat_kwh * price["flat"]
              + valley_kwh * price["valley"])

max_demand = 2150          # kW，月最大需量
demand_price = 38        # 元/kW·月，示意
demand_fee = max_demand * demand_price

total = energy_fee + demand_fee
# energy_fee = 207000 + 302400 + 98800 = 608,200 元
# demand_fee = 81,700 元；合计 689,900 元
# 其中基本电费占约 11.8%——削峰 200kW 就能省 7,600 元/月

这张账单解释了两件事：① 峰段电量占比越高，套利空间越大；② 基本电费是固定成本，削峰的收益是“确定”的，而套利收益受价差和效率影响。先做削峰、再做套利，通常是更稳的顺序。

坑：拿“峰谷价差”直接乘放电量算收益

正确算式必须扣掉往返效率：放出 1 kWh，需要先充 1/η kWh（η 约为 0.9~0.95），所以净收益是 峰价 − 谷价/η，而不是 峰价 − 谷价。项目二按 0.95 的单程效率算出约 0.73 元/kWh 的净收益（放电口径），已扣损耗。

电力市场与需求响应：钱从哪来

电价不是唯一的收益来源。理解市场结构，你才知道“预测准”和“调度对”分别值多少钱。

市场/机制时间尺度和算法岗位的关系
中长期交易年度、月度、多日电量分解、合约曲线，决定大框架
日前市场提前一天申报 96 点负荷预测直接决定申报曲线，偏差会被结算
实时市场15 分钟~1 小时超短期预测、储能实时修正
辅助服务调频、备用、爬坡储能可参与，收益与性能考核挂钩
需求响应提前邀约或实时预测基线、评估可调量、避免“响应了却拿不到钱”
绿电/绿证年度、月度绿电电量与证书，影响碳核算口径

需求响应：最容易“算对了却亏钱”的场景

需求响应（DR）是电网在高峰时段请你少用电，并按“少用的量”给你补偿。听起来简单，但结算依赖基线——也就是“如果你不响应，本来会用多少电”。基线算错，响应量就是负的。

常见基线方法

10 中取 3：取响应日前 10 个工作日中负荷最高的 3 天，同时段平均。高 5 中 10：取前 5 个工作日与前 10 个工作日中较高者。还有回归基线（用温度、日期拟合）。

为什么会被考核

如果响应日恰好降温、本来负荷就低，你“看起来”少用了很多，但那是天气的功劳，不是响应。反过来，如果基线估低了，你实际响应了也可能被判没响应。所以基线要保守、可解释、可审计。

一个现实判断

需求响应的收益通常小于“直接做储能套利 + 削峰”，但它的价值在于不投设备就能拿到补偿，且能提升园区的电网互动能力。项目二只做了储能套利与削峰，没有做 DR 结算，这是刻意收窄范围；面试时如果被问到，要能说清“为什么没做”和“要做需要补什么”。

双碳与碳核算：别把碳算错

“储能省了电费，但碳排反而增加了”——项目二的结果就是这样，很多人第一反应是算错了。其实不是。

为什么储能可能让碳排上升

储能有往返损耗（≈5%~10%），充进去的电比放出来的多。如果园区购电的排放因子是固定的，那么多买的这部分电就会带来额外排放。项目二 60 天购电增加约 29,724 kWh，按 0.5703 tCO2/MWh 计算，约增加 16.95 吨。这说明：省钱和减碳不是同一个目标，需要用分时排放因子或绿电来调和。

概念含义算法侧怎么用
排放因子每消耗 1 MWh 电对应的 CO₂ 排放量（tCO₂/MWh）电量 × 因子 = 排放量；因子随电网结构逐年更新
范围一直接排放：自备锅炉、燃气、车辆通常不在算法范围，但要能区分
范围二外购电、热带来的间接排放你的主战场：电量 × 电网因子
范围三供应链上下游排放一般不做，面试知道概念即可
绿电/绿证可再生能源电量及其凭证可抵扣范围二，但口径必须与财务/碳管理对齐
坑：用固定因子做“减碳”结论

固定因子假设“每度电的碳都一样”，但真实电网不同时段的边际排放因子差别很大（午间光伏多时更低）。用固定因子会得出“储能不减排”的结论；用分时边际因子，结论可能反过来。写报告时必须写清用的是哪种口径，不能混用。

八类典型场景：负荷长什么样，算法切在哪

同样是“用电”，不同行业的曲线形态、痛点、可用特征完全不同。面试时能说出场景差异，比背模型名更有说服力。

五个常见误解

“负荷就是用电量”

错。负荷通常是功率（kW），电量是能量（kWh）。两者差一个时间因子，混用会让所有指标失去意义。

“电表数据是准的”

错。倍率、接线、时钟、通信都会出错。行业里“先怀疑表”不是玩笑，是经验。

“节能就是减碳”

不一定。要看电网因子、时段、绿电比例。储能省电费但可能增碳，是真实存在的权衡。

“预测越准收益越高”

不一定。收益取决于误差落在哪个时段、是否触发考核、调度能否执行。谷段误差和峰段误差的价值不同。

常见问题

Q1：我不是电力专业，这些要学到什么程度？
能读懂电费单、能说清测点数据的单位与口径、知道常见设备在系统中的位置即可。不需要会设计配电系统，也不需要会算潮流。面试深挖的是“你怎么保证数据口径正确”，不是“你会不会继电保护”。
Q2：为什么项目里的电价是 1.15 / 0.72 / 0.38？
这是仿真设定，量级参考国内一般工商业峰平谷价差，不代表任何地区现行目录电价。真实项目必须以当地最新电价政策、电压等级和用户类别为准，并且要区分是否参与市场交易。
Q3：CT/PT 倍率错了，模型能发现吗？
单看一条曲线很难，因为形状可能完全正常。需要结合三条线索：① 与同类型测点的水平比值；② 与历史同期的跳变；③ 换表/改线工单记录。这也是为什么“异常识别”必须和台账、工单结合。
Q4：需量到底按 15 分钟还是 1 分钟算？
国内常见需量周期是 15 分钟，但不同地区、不同合同可能不同，也有用滑差（每分钟滚动 15 分钟）的口径。做削峰算法前必须确认当地口径，否则会把“峰值”算低或算高。
Q5：园区有光伏，负荷预测应该预测什么？
看你给谁用。如果给购电计划，要预测净负荷（用电减光伏）；如果给生产调度，要分别预测负荷与光伏。两者误差特性不同，混在一起会让模型难以解释。项目二用的是净负荷口径。
