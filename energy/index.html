关键说明

教程里的数据全部由脚本仿真生成，但生成逻辑严格对齐真实业务：15 分钟采样、双峰负荷、温度响应、节假日、采集失败、倍率错误、窃电、设备故障、峰平谷电价、光伏与储能约束。所有指标都来自本机真实训练与评估，不是编的数字。

这个岗位到底在做什么

招聘信息里的四条职责，翻译成大白话就是：把电表里脏兮兮的数字，变成能预测、能报警、能省钱的算法，并且稳定地跑在线上。下面拆成六件日常事，是为了让你看清每一块具体在做什么。

① 数据治理：先把地基打牢

测点数据清洗、缺失填充、异常剔除，建立数据质量监控。真实电表数据会有缺失、重复、倒走、负值、卡死、倍率错误——不清洗，后面所有模型都是错的。

② 负荷预测：明天用多少电

用历史负荷、气象、日历做短期预测（日前，即提前一天；24 点 / 96 点）。它是购电计划、机组安排、储能调度、需量控制的输入。

③ 异常识别：谁在偷电，哪台设备坏了

识别异常用电、偷漏电、设备故障。难点不是模型，而是没有标签、误报太多、业务不认。

④ 优化调度：什么时候充，什么时候放

结合峰谷电价、光伏、储能 SOC 与功率约束，做需求响应和储能调度，把算法变成电费单上的数字。

⑤ 服务化：让算法真正上线

把模型封装成微服务，对接平台；做版本管理、线上监控、精度与漂移跟踪、迭代调优。只会 Notebook 的人，卡在这一步。

⑥ 和业务对齐：算法要能被使用

告警要能解释、能派工单、能闭环；预测误差要能说清是天气还是数据问题。这决定了你的模型是“Demo”还是“产品”。

为什么这个方向值得投入

“双碳”、新型电力系统、园区能源管理、虚拟电厂都在扩张，而既懂时序数据、又懂算法落地的人很少。岗位要求的工具（Pandas、LightGBM、时序库、FastAPI）并不冷门，难的是把一整套链路串起来——这正是本教程要解决的。

怎么用这套教程

完全没写过代码？先读这一页

零基础补课 用 60 分钟讲完 Python 最小语法、pandas 与 Excel 的对照、机器学习 12 个核心词。读完再回来，后面的代码就不再是天书。

先读“是什么”，再动手

每章开头都会用生活化类比解释概念，然后给出“在项目里怎么用”。不要跳过概念直接抄代码，面试一问就露馅。

代码必须自己跑一遍

项目目录里有完整脚本，按 generate_data.py → train.py / detect.py → dispatch.py 的顺序运行。所有随机种子固定，结果可复现。

每章末尾的自测题要能口述

不是背答案，而是能用自己的项目举例。比如“为什么 MAPE 在夜间会变大”，要能指着图解释。

最后把两个项目讲成故事

背景 → 难点 → 方案 → 结果 → 取舍 → 如果重做会怎么改。这是面试官真正想听的。

三条阅读路线，按你的习惯选

路线 A：先建框架，再看项目

第 1 → 2 → 3 → 4 → 5 → 6 章，把“数据怎么来、模型怎么建、服务怎么上”走通，再读项目一、项目二，最后读第 9 章。好处是每个概念都有铺垫，不会在项目里被术语卡住。

路线 B：边学边做，用项目驱动

第 1 → 2 → 3 → 4 → 项目一 → 5 → 项目二 → 6 → 9 章。每学一块就落到项目里，成就感强；遇到不懂的术语再回查第 1 章。

路线 C：先补行业，再补短板

第 1 → B1 → 2 → 3 → 4 → 5，然后按需读 B2（数据）、B3（算法）、B4（优化）、B5（工程），最后回到项目与第 9 章。适合跨行转岗、担心“业务说不清”的人。

三条路线都对，唯一不建议的是只读前两章就停。

几点必要的诚实说明

仿真数据的边界

本项目注入的异常信号较强（窃电约 -35%、倍率 ×3、故障 -45%），因此 F1 偏高。真实场景中窃电可能只让读数偏低 5%~10%，需要更细的特征（台区线损、分钟级电流、同表历史同期）与现场核查。教程会明确标注这些差异，避免你面试时把仿真结论当成真实世界的普遍规律。

如何复现全部结果

环境：Python 3.10+，依赖 pandas / numpy / scikit-learn / lightgbm / statsmodels / matplotlib / scipy / fastapi / uvicorn。在每个项目目录按 README 的顺序运行即可，数据与图表都会重新生成。教程中展示的每个数字都来自这些脚本的输出。
