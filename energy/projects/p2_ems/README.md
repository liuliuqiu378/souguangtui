# 项目二：工业园区 EMS —— 数据治理 + 异常用能识别 + 储能调度

面向工业园区 EMS 的行业项目，覆盖完整链路：脏数据治理 → 质量评分 → 日粒度异常识别 → 15 分钟粒度线性规划调度。数据为仿真生成，异常可评估、结果可复现。

## 方法要点

**质量分**：`score = 100 × (1 − missing_rate)`，当前仅衡量完整性。生产上建议扩展为完整性、合理性、稳定性、时效性多维加权。

**异常识别**：

- 日粒度特征：均值、最大值、P95、CV、夜间占比、最长恒定段、越界点数、完整性、水平突变、同业偏离、尖峰倍数。
- 规则：同业偏离 ≥20%、尖峰倍数 ≥2.5 或超容量、恒定段 ≥20%、完整性 <85%。
- 孤立森林：300 棵树、`contamination=0.02`、`random_state=42`，阈值取校准期 99% 分位 = 0.61867。
- 组合：规则 OR 模型；高严重度（水平突变/尖峰）当天推送，中严重度进周报。

**储能调度**：

- 目标：最小化 `Σ 电价 × 购电 × Δt + 需量电价 × 全天峰值`
- 约束：功率平衡、SOC 递推、SOC 10%~90%、首末 50%、充放电 ≤1000 kW、`grid ≤ peak`
- 电价：峰 1.15（8-11、17-21）、平 0.72、谷 0.38；需量 1.2 元/kW·日
- 求解器：`scipy.optimize.linprog(method="highs")`

## API

```bash
# 异常判定
curl -X POST http://127.0.0.1:8001/v1/detect \
  -H "Content-Type: application/json" \
  -d '{
    "meter_id": "M005", "date": "2024-08-05", "meter_type": "office",
    "capacity_kw": 128,
    "readings_kw": [0, 0, "... 共 96 个 ..."],
    "baseline": {"peer_median_kw": 30.2, "ratio_base": 1.05,
                 "mean_kw": 31.0, "max_kw_14d_median": 34.5}
  }'

# 质量报表摘要
curl http://127.0.0.1:8001/v1/quality

# 单日调度
curl -X POST http://127.0.0.1:8001/v1/dispatch \
  -H "Content-Type: application/json" \
  -d '{"load_kw": [0, "... 96 个 ..."], "pv_kw": [0, "... 96 个 ..."]}'
```

`baseline` 不传时服务会降级（`degraded: true`），仅用当日数据与自身水平突变判定，结果会偏保守。

## 已知局限（面试必须主动说）

1. **F1 偏高**：注入信号强（−35%、×3、−45%、8 小时卡死）。真实弱信号场景通常只有 0.6~0.8。
2. **尖峰漏报 4 个**：全部是路灯低负荷时段，单点 ×7 不改变日最大值，`spike_score≈1`。修法是逐点相对邻域突增检测。
3. **恢复期误报**：M005 的 4 个误报源于异常期污染了 14 天最大值基线；生产上基线要剔除已告警日。
4. **质量分单一**：只看完整性，未覆盖合理性与稳定性。
5. **调度用完美已知的负荷与光伏**：未考虑预测误差；生产上需滚动优化与 SOC 余量。
6. **碳排增加**：往返效率约 0.9，套利导致购电量增加；固定碳因子 0.5703 kgCO₂/kWh 下碳排上升。省电费与降碳不是同一目标。
